---
id: D-050
title: "WP-06: `fleet done` runs the check locally, and its exit code still means delivery"
phase: "WP-06"
status: alive
---

- **The one verb that runs something runs it in the CLI process.** `fleet done <task-id> "<check>"` executes the block's check via `sh -c` in the worker's own worktree, then composes a receipt and sends it to `orch` as an **ordinary `Op::Send`**. The hub never executes anything and never sees the command. That is not a nicety: a hub that ran commands would be the supervisor Phase 5 deleted, with a shell attached.
- **The delivery contract did not move, and this is the place it would have.** `fleet done` is the only verb where a model could reasonably assume the exit code describes the *check*. If it did, a failing check would exit non-zero, both briefs promise that means *not delivered*, and the worker would resend a receipt that had already arrived — D-034's shape in a new place. So: **a failing check still produces a receipt**, `op()` returns `Err` only when nothing could be checked at all, and the check's own result travels in the body (`· exit 7`). Pinned three times — in `done.rs`, in the CLI's `report` test, and as a literal in the worker brief (`never in the exit code`).
- **The receipt is evidence with no opinion in it.** `[receipt] task-1-0 · fleet/worker-2 @ a1b2c3d · exit 0`, then the command, then a fenced tail. There is deliberately no `passed` bool — a bool would be the CLI forming a view about somebody else's criteria, and judgement is the reviewer's (Tier 1.8). A signal-killed command is rendered `killed by a signal` rather than an invented `exit -1`. Uncommitted changes are named on the receipt, because review reads the *commit* the receipt cites and a hash that does not contain the checked work sends a reviewer to honestly review the wrong thing. No git, no invented hash: `not a git checkout — nothing here can be reviewed by branch`.
- **2 KB of tail, and it says what it dropped.** The tail rather than the head, because that is where the summary and the first failure are; a head-capped build log is all compiler noise and no verdict. It reports the dropped byte count for the same reason `accepted` never renders as "delivered" (L3) — a tail pretending to be the whole output is the same lie one layer down. The cap slices on a char boundary, escapes are stripped before anything is measured (legibility and budget, *not* security — the pty boundary is still `message::sanitize`, untouched), and the fence grows past any backtick run inside the output.
- **No deadline on the check** (Tier 1.4's argument, reused): a ceiling could only report failure for a command that then finishes. The pane's own Bash tool has a timeout and it is the caller's to set.
- **The message path's diff is empty, and this time so is the wire.** Zero diff in `message.rs`, `command.rs`, `wire.rs`, `task.rs`, `hub.rs`, `deliver.rs`, `pty.rs`, `pane_messaging.rs`, `panes.rs`, `fleetor-db` and `ui/`. `fleet done` needed no new op, no new `OpResult` variant and no event kind — it reuses `Op::Send` and gets back `Delivered`, so WP-05's `Recorded`/`Board` naming stays coherent by not being touched. `src-tauri`'s only changes are the fallback warning and one test fixture's verb list.
- **Cost, measured — the third overrun in a row.** Rendered orch **2,228 → 2,542** and worker **1,591 → 1,967** (DeepSeek Flash tokenizer, `examples/system-prompt-spike/count.py`): **+314 and +376**, against a budgeted ~150 *across both*. A tightening pass ran before the number was recorded (−21 orch, −25 worker) and found almost nothing, which is the finding: the overrun is structural, not fat. Two prompt sections is what a verb costs when the verb has a protocol — finish, report, ask, review, merge — rather than a syntax. `OVERNIGHT-QUESTIONS.md` Q-3 carries it, because Q-2 had already told this package the headroom was gone and it spent it anyway.
- **Verified:** 165 workspace tests and 83 shell tests green (42 CLI, 89 core, 18 pane-messaging, 11 real-pty), `tsc --noEmit` and `vite build` clean. Delivery-contract tests untouched and green.
