id: D-043
title: "the panes stop appending to Claude Code's system prompt and replace it"
phase: "meta"
status: alive
---

- **The default that lost was `--append-system-prompt`.** Our brief sat *after* CC's own system prompt and could not override it, which was the right shape while the brief was "a job description handed to an agent that already knows how to work". WP-02 needs the prompt files to *be* the pane's identity — a vision-partner orchestrator and workers with a stated culture are not a postscript to someone else's prompt. Operator decision, 2026-08-06. Tier 1.2 sanctions it: `building.md:16` puts the system prompt in harness territory, and this is a supported CLI flag, not a patched CC.
- **Measured before switching, and the measurement changed the plan.** `examples/system-prompt-spike/probe.py` points `ANTHROPIC_BASE_URL` at a local recorder, so the assembled system prompt is a file on disk rather than an inference from model behaviour, and two runs differing only in the flag give an exact diff. `docs/system-prompt-notes.md` has it all, version-stamped **CC 2.1.223**.
- **`--system-prompt` changes exactly one thing.** CC's guidance leaves the third system block — 6,866 chars down to 364. Tools (28 definitions), memory files, the skills listing, the agent-types block and the entire first-user-message `<system-reminder>` are **byte-identical** under either flag. "Replace the system prompt" means "replace CC's guidance", not "replace everything CC injects", and that is what made the switch cheap.
- **Two surprises, both of which saved work.** The **git-status section survives** — `--exclude-dynamic-system-prompt-sections` says it is "ignored with `--system-prompt`", which describes that *flag* being ignored, not the section being skipped. So a worker is still told its branch, and WP-02's plan to restate it was dropped. And **the project's `CLAUDE.md` still loads**, for orch and workers alike, because it never travelled in the system prompt to begin with — the open question about orch losing its skills and memory answered itself.
- **`cwd` is the one real loss.** CC's `# Environment` section carried it and is gone; nothing else in the request names the working directory except, accidentally, the paths of any `CLAUDE.md` that happened to load. So `{cwd}` is now a required placeholder in both templates, filled at the spawn site from the same path handed to `CommandBuilder::cwd`.
- **`prompts/scaffolding.md` is a third locked fragment.** It restates what a pane no longer inherits and would visibly miss: tool discipline and parallel calls, that a denied call was refused rather than lost, that a long conversation is summarized rather than ended (a worker that thinks it must wrap up early abandons work mid-task), faithful reporting of outcomes, and the security-refusal and pronoun defaults. Required in both templates for the same reason `{delivery_contract}` is: an operator rewriting prose should not be able to silently remove a pane's working posture. Five pinned literals guard the clauses whose absence changes behaviour.
- **CC's `# Memory` section is deliberately not restated.** A worker's memory directory lives under that slot's isolated `CLAUDE_CONFIG_DIR`, so anything written there is invisible to every other pane and to the operator — and Tier 1.8 says shared knowledge merges only after review. For orch it is the operator's own, and the fleet has no business reimplementing it half-way. Reversal is one fragment in `prompts/` if an operator notices their orch pane stopped remembering across sessions.
- **No fallback ladder needed.** WP-02 held a per-pane-class split in reserve (workers replace, orch appends) in case `--system-prompt` degraded interactive behaviour. Nothing degraded: the pane reaches its prompt, runs tools, keeps `--permission-mode auto`, and both `/clear` and `/compact` still work. All five panes replace, and the split stays unbuilt.
- **What would reverse it.** A CC release that makes `--system-prompt` print-mode-only, or that starts dropping something load-bearing along with the guidance. The detection is re-running the spike on a CC update — `docs/system-prompt-notes.md` is version-stamped for exactly that, and `building.md` §8 already lists flag drift as a live risk. The retreat is one string in `spawn.rs`, since the fragments render either way.
- **Cost, measured:** the rendered orch brief goes 487 → 878 tokens and the worker 506 → 868 (DeepSeek Flash tokenizer, via `examples/system-prompt-spike/count.py`). Against the ~6.5 KB of CC guidance that stopped being sent, both panes now start a session *smaller* than before.
- **Verified:** 38 workspace tests for `fleetor-core`, 44 + 9 shell tests green. The spawn-site test now pins `--system-prompt`, and asserts `--append-system-prompt` is absent rather than only that the new flag is present — a spawn path that passed both would satisfy a one-sided check.
