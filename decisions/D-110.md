---
id: D-110
title: "STANDING RULE: nothing starts an agent at launch — an agent acts only after a message someone sent it"
phase: meta
status: alive
---

- **The rule.** The app never prompts, wakes or messages an agent on its own initiative. After a new fleet or a reopen, every pane waits. orch begins its startup work (the task triage included) when it receives its first message from the operator, and a worker begins when orch or a peer messages it.
- **Scope: universal.** The operator set this on 2026-10-07 as a rule all future work must follow, in every slice and every PRD. A feature that seems to need an automatic start is designed around the first message instead: put the instruction in the brief, to be acted on when that message arrives.
- **What it forbids.** A "session started" message sent by the app; a timer, hook or store subscriber that types into a pane; anything that reads tasks, settings or run state and then prompts an agent. This restates and widens the task PRD's out-of-scope line "an app-driven wake at startup".
- **What it does not forbid.** Delivering a message a person or an agent sent, including the mechanics of D-098 (pressing a pane that will not settle on a delivered message). Rendering state on screen. Briefs that say what to do first.
- **Why.** The operator stays the one who starts work. A fleet that begins spending tokens and changing a repository because the app opened is a fleet acting without anyone having asked.
- **Reverses only if.** The operator says so explicitly. No other decision may relax it by implication.
