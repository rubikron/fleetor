---
id: D-105
title: "a release is one chain entry with four required fields; the hub settles \"where\" and who it is on behalf of"
phase: S2
status: alive
---

- **What.** `fleet task release <n> --why … --done … --left … [--where …]` writes one `released` chain entry that returns the task to planned and clears its owner. All four fields must be non-empty. The CLI always sends its own checkout's branch and commit; the hub uses that only when the sender is the task's owner in this lineage, and otherwise requires `--where`. When the sender is not the owner, the entry names the owner in `on_behalf_of`. Anyone may release a task; a goal is refused.
- **Why.** Only the hub knows who the owner is, so the CLI cannot decide whether its own checkout says anything about the task. One entry rather than a release plus a status change keeps the chain reading as one event (PRD story 37).
- **Deferred to S3.** "Where" from the task's latest receipt. Receipts are not chain entries until S3, so in S2 a release by anyone but the owner needs `--where`.
- **Reverses if.** Live runs show orch unable to find a crashed worker's branch and commit to type.
