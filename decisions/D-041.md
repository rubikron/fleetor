---
id: D-041
title: "startup orphan sweep: the teardown that runs when teardown can't"
phase: "meta"
status: alive
---

- **The problem was structural, not a bug.** Close-time teardown (`on_window_event` + `RunEvent::Exit`, both calling `pty::kill_all`) only runs if the process gets a chance to — Force Quit, `kill -9`, and a crash all skip it, and a leaked `claude` with no terminal and nobody watching is a bill that keeps growing. That same risk was already on `building.md`'s table with "Startup sweep" listed as the planned fallback; this implements it.
- **Two gaps closed at once.** (1) On macOS, `Cmd+Q` and Dock → Quit bypass `WindowEvent::CloseRequested` entirely — a documented, currently-open Tauri bug (tauri-apps/tauri#9198, #13778). Without `RunEvent::Exit` as a backstop, quitting the app any way other than clicking the close button leaked every pane. (2) Even with both close hooks, a crash or Force Quit still skips them by definition. The startup sweep catches that.
- **`src-tauri/src/orphans.rs` (new).** Every `PaneRegistry` spawn/kill/kill_all durably writes the current set of live pane pids to `~/.fleetor/_shell/panes.pids`. At next launch, before spawning anything new, `orphans::sweep()` reads that file, verifies each pid is still alive **and** still actually a process named `claude` (via `ps -o comm=`), then `killpg`s it. The identity check guards against pid recycling — a stale pid could since have been reassigned to an unrelated process.
- **The registry path is now explicit in `PaneRegistry::new`.** Deliberate refactor: tests were writing into the operator's real `~/.fleetor/_shell/` on every run. Now every test builds its own registry around a scratch path, and `kill_all` clearing the registry is verified by reading the on-disk file back (`spawn_kill_and_kill_all_keep_the_pid_registry_in_sync_with_reality`).
- **One gotcha survived the spike and is documented.** A pane that exits *naturally* (the pty EOFs, pump thread notices) does not trigger a registry rewrite — only explicit mutations do. Harmless: the sweep's liveness+identity check already treats "gone" as a no-op, so a stale entry costs nothing on the next launch. A comment on `record_live_pids` explains why that's fine rather than a bug.
- **Testing the `killpg` itself required real processes, not mocks.** A copied binary loses its code signature on macOS and behaves unpredictably, so the test can't just `cp /bin/sleep ./claude`. Instead, `reap_if_named` (and now `sweep_at_named`) take the expected name as a parameter, so the tests exercise the real mechanism against `/bin/sleep` directly. One test that polled `kill(pid, 0)` to check death was fooled by zombies — switched to `try_wait` since we're the parent in that test.
- **Verified:** 45 tests total (36 lib + 9 integration), all green. Coverage of the new module: registry round-trips, sweep on absent file, sweep on empty file, sweep with a dead pid, sweep with a live non-matching pid, sweep with multiple live matching pids, `write_registry` failing closed when its parent can't be created, the `killpg` mechanism itself against a real process, and the full `spawn`/`kill`/`kill_all` wiring keeping the on-disk registry in sync with reality.
