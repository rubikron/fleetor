title: "WP-06: the reviewer is named in the assignment message, not in a field on the block"
phase: "WP-06"
status: alive
---

- **The default that lost was the spec's own recommendation.** `06-receipts-review-merge.md` open question 4 recommended a `reviewer` field on the task block, and WP-05's schema landed without one. Adding it was the smaller-looking change and the wrong one. Tier 2 — schema and prompt text — so this is the record, not a request.
- **A `reviewer` field is the first field on the board that something would be tempted to read.** WP-05's whole finding (D-047) is that the board is a **diary, not a dispatcher**: nothing reads it back to permit, order or refuse anything, and its tripwire list bans routing by task state. `reviewer` is the one field that begs for it — the obvious next commit is a check that the reply came from the named pane, and that is a review gate in code, which this package's guardrails rule out by name. `outcome`/`technical`/`semantic`/`worker` describe the *work*; `reviewer` would describe *who may act*, which is a different kind of field wearing the same clothes.
- **So the duty is created where the assignment already is.** D-047 already established that posting a block assigns nobody and the `fleet send` is the assignment. The reviewer rides in that same send — "worker-3 reviews this when you are done" — which keeps one act, one message, and one attributed author. `prompts/orch.md` carries the rule and its reason (a peer, never the block's author, never orch itself: an orchestrator reviewing its own decomposition finds what it expected to find), and `prompts/worker.md` tells a worker to ask if it was not named. Nothing enforces any of it; the review reply is an ordinary message, and the board records what happened via `--note`.
- **The side benefit is that WP-05's tests did not move.** `TaskBlock`, its serde shape, `task_board.rs` and the Tasks view are byte-identical — a schema change would have touched a landed package's pinned tests to buy a field whose best use was one nobody is allowed to build.
- **What would reverse it.** Live evidence from WP-09 that reviewers are simply never named — a fleet where `done` goes unreviewed because the instruction sat in a message the worker had already compacted away. The fix would then be a field on the block *plus* the discipline to leave it unread, and the second half is the hard part. The cheaper intermediate fix is prompt text, and it is where this would be tried first.
