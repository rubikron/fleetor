---
id: D-059
title: "the archive is written for an agent to read, and it takes the workers' transcripts with it"
phase: "meta"
status: alive
---

- **What changed.** An archived run stops being one SQLite file and becomes a readable directory. Rotation now also writes `events.json` (the whole log as a JSON array, each row the event exactly as it crossed the wire plus its `seq` and `ts` columns) and `manifest.json` (the run's metadata, what each file in the directory is, and what the data does *not* cover), and **moves** each worker's Claude Code session transcripts from `pane-config/worker-N/projects/*/` into `runs/<id>/transcripts/worker-N/`. Moved rather than copied: transcripts live in a config dir that outlives a run, so copying would leave every archive carrying its predecessors. `RunRecord` gains a `transcripts` count, the History rows gain an Export button, and `run_export` saves `events.json` wherever the operator points via the Rust-side dialog — a copy of the file that already exists, never a second serialization, so "download the logs" and "what an agent reads" cannot drift into two formats.
- **Why the default lost.** The operator's stated purpose for History is that *agents* read and evaluate past runs, humans later. That inverts the design: the primary artifact is a directory readable with `cat` and `jq` — no SQLite, no running app, no GUI to drive to produce the reader's own input — and the download button becomes a convenience over it rather than the mechanism. The event log alone was also the wrong evidence base: it records what the panes said to each other, and an evaluator asking why a run went the way it did needs what each pane *did* between saying things, which only the transcripts hold. `events.json` is deliberately re-emitted from parsed JSON rather than re-serialized through `FleetEvent`, so a field a future build adds survives being read by an older one.
- **What would reverse it.** Disk: every run now stores its log twice plus its transcripts, and a long run's transcripts dwarf both. If that bites, the answer is generating `events.json` on demand and keeping `state.db` as the only stored copy — at the cost of the property that makes this useful, so measure the actual sizes first. **The known gap, unreversed:** `orch`'s transcript is *not* archived, because it lives in the operator's own `CLAUDE_CONFIG_DIR` outside `~/.fleetor` and reaching in there crosses Tier 1.1's boundary. The pane doing the deciding is the one whose reasoning the evaluator cannot read. Closing it needs an operator decision, not a builder's.
