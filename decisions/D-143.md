---
id: D-143
title: "an opencode seat runs on the operator's real data dir; only its configuration is relocated"
phase: "WP-32"
status: amended by D-146
---

- **What.** No private `HOME` and no private `XDG_DATA_HOME`: every opencode seat reads the operator's `~/.local/share/opencode`, so the Go login works. The seat's configuration is its own: `OPENCODE_CONFIG_DIR` points at the seat dir (plugin, agent), `OPENCODE_CONFIG` at the operator's `opencode.json` (read, never written), and `OPENCODE_CONFIG_CONTENT` carries the seat's overrides.
- **Why.** The operator's call, 2026-11-02, following D-128. The login lives in `opencode.db` (`credential`, `account` tables) beside every past session. Rejected: copying only the credential rows (FLEETOR would depend on opencode's migrating schema, and a change logs every worker out silently); copying the whole 42 MB database into each seat. `OPENCODE_CONFIG` is there because a relocated config dir drops the operator's global config and its providers (`opencode-spike-notes.md` §3).
- **Cost.** Worker sessions appear in the operator's own opencode history, and a worker can read what the Fence hides (`~/.ssh`, profiles). Writes are D-142's.
- **Reverses if.** opencode gains a credential file or a data-dir variable for the login alone.
