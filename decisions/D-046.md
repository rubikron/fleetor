title: "WP-04: the context gauge is `AppCommand::Roster`'s job, not a new channel; the window is our own 128k, not CC's 200k guess; the live gauge never estimates"
phase: "WP-04"
status: alive
---

- **The default that lost was "a live figure is worth an educated guess when the real one is missing."** The requirements doc's own design sketch floated a chars/4 fallback for the live gauge when a transcript's `usage` field is absent. That default lost here: the live gauge reports a real transcript-derived number or nothing, full stop — the chars/4 estimate survives only for the spawn-time counter, over text already held in memory, always labeled as exactly that (a brief's size, not a pane's total starting context). "Absent, never faked" (`decisions.md` L155) is the harder rule to violate by accident when the two instruments never share an estimation path.
- **Spiked first, and the spike settled the one open question that mattered.** `examples/context-gauge-spike/probe.py` spawned a real worker-postured `claude` against DeepSeek Flash under an isolated `CLAUDE_CONFIG_DIR` and inspected what landed on disk. `docs/context-gauge-notes.md` has it all, version-stamped **CC 2.1.223**. The path is `<CLAUDE_CONFIG_DIR>/projects/<slug>/<uuid>.jsonl`, `<slug>` being the resolved absolute cwd with every `/` and `.` replaced by `-` (verified character-for-character, and the same canonicalization `spawn::project_key` already does for the `.claude.json` trust key — reused, not re-derived). Usage lives at `message.usage` on `type: "assistant"` lines only.
- **The load-bearing finding: `input_tokens` alone lies once caching starts.** Two live turns measured `input_tokens` going 27,723 → 96 while the conversation only grew — DeepSeek's endpoint moved the cached remainder into `cache_read_input_tokens` (27,648). A gauge reading `input_tokens` in isolation would have shown worker-2 *emptying out* the instant it got cheaper to serve, which is backwards. `context_gauge::last_turn_usage` sums `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`; that sum tracked the growing conversation correctly (27,723 → 27,744) and is pinned by a test (`usage_is_the_sum_of_all_three_input_fields_not_input_tokens_alone`) precisely because the wrong number *looks* plausible.
- **The window is `WORKER_WINDOW_TOKENS = 128_000` in `src-tauri/src/context_gauge.rs`, a Tier 2 constant, not a read.** WP-02 already found (`docs/system-prompt-notes.md` §4) that Claude Code does not recognize `deepseek-v4-flash` and silently assumes 200k for its own auto-compact bookkeeping — restated here because this package is where a second component could have quietly inherited that same wrong assumption. Nothing in the transcript states a window (confirmed by this spike: none of the three `system`-typed lines mention it), so there was never a number to read; 128k is this project's own stated guess, picked for the DeepSeek family's published range rather than CC's guess for an unrecognized name. **Reverses if:** a real published `deepseek-v4-flash` context window is confirmed, or a live shakedown shows compaction happening at a visibly different point than 128k would predict.
- **Sampling is a directory scan at ask time, never a filename cached from spawn.** `/clear` resets a pane's session; whether Claude Code opens a new `<uuid>.jsonl` for that or keeps writing the one it had was not worth a spike run to settle (this package's probe budget was 1 of the allowed 4) — `context_gauge::latest_transcript` picks the most-recently-modified `*.jsonl` under a pane's project directory on every call, which is correct either way at the cost of one `read_dir`.
- **One seam answers both askers.** `fleet_roster` (new Tauri command, for the UI's ~10s poll) sends the identical `AppCommand::Roster` into the same channel `Hub`'s socket-side `fleet roster` already used — both converge on `deliver::spawn_delivery`'s one `Roster` arm, which is the only place a worker's transcript is sampled (`GaugeSources`, populated by `crate::fleet::spawn_pane`) and the only place the once-per-session ~80% Notice can be guaranteed not to double-fire regardless of which caller asked first. Zero new verbs, as scoped: `PaneEntry` gained an `Option<ContextGauge>` field (`#[serde(skip_serializing_if)]`, so an unsampled pane's JSON omits the key rather than sending `null`), threaded through the existing `Op::Roster` wire op unchanged.
- **The message path's diff is empty, literally.** `crates/fleetor-core/src/message.rs`, `crates/fleetor-core/src/command.rs` and `src-tauri/src/pty.rs` have zero changes (checked via `git diff --stat`); `crates/fleetor-server/src/hub.rs`'s `Send`/`Broadcast`/`Reply`/`Cmd` arms are untouched (checked via `git diff`); `src-tauri/src/deliver.rs`'s `Deliver`/`Command` match arms carry no added or changed lines — only the `Roster` arm and the module's imports/doc grew.
- **The spawn-time counter is the brief's size, not the "Loadout" doc's full itemized breakdown.** The autonomy-designs doc's own verdict on Loadout was "ship the counter, defer the rest" (the delete-and-rebuild config manager, the itemized `brief · house notes · role · repo CLAUDE.md · skills` breakdown) — this ships exactly the counter: one `Notice` per pane launch reporting the rendered brief's chars/4 estimate, and — for a worker only — what percent of `WORKER_WINDOW_TOKENS` that is. Not a claim about the pane's *total* starting context: tool definitions and CC's fixed first-message scaffolding are real (`system-prompt-notes.md` measured ~18.6 KB of it) and roughly constant per launch, but counting them needs a tokenizer this package deliberately does not add (requirements doc, Out of scope). The Notice text says "brief," not "context," on purpose.
- **The restart-counter stretch item is not shipped.** It was explicitly "only if trivial." It is not: nothing today emits `FleetEvent::PaneState` (grepped — the variant exists in `event.rs`, unused), so a counter would need new event-emission wiring rather than reading one that already exists. Left for whichever package actually needs it, with the reason recorded rather than silently dropped.
- **Verified:** 101 crates-workspace tests and 82 shell tests green (`cargo test --workspace`; `cd src-tauri && cargo test`), `tsc --noEmit` and `vite build` clean (62 modules). New coverage: the exact cache-accounting finding above, pinned against a fixture built from the spike's own transcript shape; the slug-encoding rule cross-checked against `spawn::project_key`; absent-never-faked for a pane with no source, no transcript file, and a transcript with no completed turn; the most-recently-modified file winning when more than one session file exists; the once-per-session Notice holding across three repeated over-threshold asks in one test; and a real-pty end-to-end test (`src-tauri/tests/panes.rs`) proving a live `AppCommand::Roster` round trip surfaces a seeded worker's gauge while orch and an unrecorded peer both stay `None`. Orch brief measured 1,885 → **1,910** tokens (+25, budgeted ~30); worker unchanged at 1,343 (only `orch.md`'s roster line moved).
- **What would reverse it.** A CC release that changes the transcript path/slug rule or the `usage` field shape — `docs/context-gauge-notes.md` is version-stamped for exactly that. A live shakedown showing the 128k window constant is materially wrong for the real model. Evidence that the UI's 10s poll is too chatty or too stale for how operators actually watch a fleet — the interval is a single constant (`useContextGauge.ts`), cheap to change.
