---
id: D-127
title: "the probe's facts are MachineFacts { home, path }, and codex's probe still inherits CODEX_HOME"
phase: "WP-30"
status: alive
---

- **What.** (a) The probe's facts type is `MachineFacts { home, path }` in `harness.rs`, built once in `discover_for_the_gate`; issue #52 defined no facts type, and these are exactly what both probes needed. (b) Codex's probe child process (`codex doctor`) still inherits the app's `CODEX_HOME` and working directory. Placement reads nothing itself, and what the vendor binary reads from the environment it inherited is the vendor's.
- **Why.** Rejected for (b): a `codex_home` field on `MachineFacts`, which puts a vendor fact in the shared struct against D-090's vendor/shared line; and clearing the probe's environment, a behaviour change that would stop an operator's own `CODEX_HOME` being honoured.
- **Also.** (c) Each harness's literals-tripwire needles are a `NEEDLES` const beside its spec, reached through an undefaulted `Harness::literal_needles()`, because `tests/harness_literals.rs` is an integration test and can only see them through the public trait; issue #52 named no mechanism.
- **Reverses if.** A probe's result is shown to depend on an inherited variable in a way that misleads the gate, or a third harness needs a fact the struct can't carry.
