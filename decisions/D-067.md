---
id: D-067
title: "worktrees namespaced by target repo"
phase: "meta"
status: alive
---

- **What changed.** `worktree_dir(slot)` became `worktree_dir(target, slot)`. Worker worktrees now live at `~/.fleetor/_shell/worktrees/<target-slug>/worker-N` where `<target-slug>` is the target directory name plus a 4-character hex hash of the canonical path (e.g. `my-project-a3f2`). `target_slug()` in `fleet.rs` computes it.
- **The default that lost was a flat `worktrees/worker-N`.** Switching targets left stale worktrees from the old repo on disk. `ensure_worktree` saw `.git` and short-circuited, so workers ended up in checkouts of the wrong repo. The alternative — detect-and-recreate — would have torn down and rebuilt worktrees on every target switch, losing any uncommitted worker state and adding teardown logic. Namespacing preserves each target's worktrees independently, so switching back reuses them.
- **What would reverse it.** Evidence that the disk accumulation matters (each target's four worktrees persist until `rm -rf ~/.fleetor/_shell`), or a target whose directory name plus hash collides with another in practice — which would require two targets whose canonical paths produce the same 16-bit hash *and* share a directory name.
