- **What.** `CodexCli::resume_args` took a `Seat` named `_seat` and threw it away, so a reopened codex worker came back on the operator's default model and **without `--dangerously-bypass-hook-trust`** — the argument that makes the fleet's own `PreToolUse` hook run at all (C46, C48). It now carries both, the way `ClaudeCode::resume_args` already carried its model and permission flag. First item of WP-29 (`docs/roadmap/29-codex-history-parity.md`), which is the second half of D-087.
- **The seam was right and that is exactly why this survived WP-27.** Nothing here is a new abstraction: `resume_args` is a trait method, `spawn::args_for` already asked for it polymorphically, and conformance already ran over both harnesses. What conformance never did was compare `resume_args` against `command_args` for the same seat, so a slot filled with less than the other vendor put in it read as green. `checkpoint_15_a_reopened_pane_keeps_every_posture_argument_a_fresh_one_gets` now asserts containment — every argument a fresh launch carries, minus the brief and its flag, must survive a reopen. **Mutation-checked:** re-dropping the bypass fails it by name.
- **Both flags were verified accepted after the subcommand rather than assumed.** `codex resume --help` at 0.153.4 lists `-m, --model <MODEL>` and `--dangerously-bypass-hook-trust` among `resume`'s own options. This mattered: a top-level flag appended after a subcommand clap had not marked global would have failed every reopened codex pane at spawn, and the failure would have looked like a dead terminal. Read from `--help` on both installed binaries (`/opt/homebrew/bin/codex`, `~/.local/bin/codex`, both 0.153.4), resolved absolutely per C47 — the PATH `codex` is a cmux wrapper.
- **A second reason not to pass a brief, found here.** R13 already forbade it; `codex resume` also takes an optional `[PROMPT]` positional, so a brief would not merely duplicate instructions, it would be typed as the session's next user turn.
- **Not verified, and deliberately not measured first.** WP-29's open question 2 asked whether a reopened codex pane's guardrail still fires *without* the bypass — that is unmeasured, and this entry does not answer it. Parity with the fresh-launch argv was chosen over measuring first because it is the reversible direction: if the flag turns out unnecessary on resume, dropping it is a one-line change with a comment, whereas shipping a guardrail-less pane is the failure R13 guarantees nobody in the pane reports. The measurement stays open as WP-29's question 2.
