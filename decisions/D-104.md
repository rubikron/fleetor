---
id: D-104
title: "S1 wiring: the store sits under `targets/<slug>/`, the UI reads it through one snapshot command, and the operator writes through the hub"
phase: S1
status: alive
---

- **What.** A launch opens `~/.fleetor/targets/<target-slug>/tasks.db` for the fleet's fixed target (same slug as worktrees) and writes the target's absolute path beside it as `target.txt`. Run id is the chain's `run`; the sessions id is its `lineage`. Entries reach the UI on `fleet://task`. `fleet_tasks` returns the whole store plus whether it is writable: the live fleet's, or with no fleet the gate target's, opened read-only and never created. The UI merges that snapshot with the pipe by sequence number and clears on every launch. `fleet_task` sends one operator change through the hub as `operator`. The Tasks view has a new goal / new task form, comment, edit, Close and Reopen; with no fleet every control is disabled with "start a fleet to change tasks".
- **Calls made.** A task store that will not open does not fail the launch: an Error notice goes on the feed and `fleet task` refuses. The operator's Close is `dropped` and Reopen is `planned`. "Message the owner with this task" is an unticked choice that sends an ordinary operator message after the task is recorded. The UI fold in `ui/src/fleet/board.ts` mirrors the Rust one; Rust is the authority.
- **Seen live, 2026-10-06.** The operator ran a fresh fleet on a two-task goal: orch recorded the goal and both tasks, workers took them up and marked them done, comments and the merge note landed in the chains, and the Tasks view showed all of it. A second pass the same day covered the operator's controls, the status filter, task entries in Activity, and records surviving a restart; the operator reported all of it working.
- **Archive.** Archiving a run writes `tasks.json` beside `events.json`: the goals and tasks whose chain has an entry from that run, each with its whole chain, read from the target's store read-only. History's task count comes from that file and falls back to the run-log digest for runs archived before it existed. A run with no recorded target gets no file and an Info notice.
- **Activity.** The feed shows the current lineage's task entries, placed by arrival: each sits after the last run-log event seen before it, because run-log events reach the UI with no timestamp. Exact on a fresh launch; on a reopen the lineage's earlier entries arrive together at launch.
- **Filter.** The task list narrows to All, Planned, In progress or Done. A goal stays while one of its tasks matches, and its counts still cover all of them.
- **Open.** Home's worker cards still count legacy run-log task events. The Running now count waits on the launch PRD's History row states, which are not built yet.
- **Reverses if.** A missing task store proves worse than a failed launch in practice; then opening it becomes fatal.
