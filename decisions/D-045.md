---
id: D-045
title: "`fleet cmd`: a command channel that is not the message path"
phase: "meta"
status: alive
---

- **The default that lost was "the router chops the prefix off for slash commands."** That framing describes a content-inspecting transform *inside* the delivery path — the shape Tier 1.4 has rejected twice. This lands the capability the other way round: a separate verb, a separate `Op::Cmd`, a separate `AppCommand::Command`, a separate hub arm and a body that was never framed. **Commands are not messages; nothing is chopped.** `Message::framed`, `sanitize`, `write_paste` and `Op::Send`/`Broadcast`/`Reply` are byte-identical — verified as an empty `git diff` on `crates/fleetor-core/src/message.rs` and `src-tauri/src/pty.rs`, plus a grep over `hub.rs` and `wire.rs` showing no line of the message arms changed.
- **`fleet cmd <pane|self> "<command>" --why "<reason>"`.** `--why` is `required` in clap, not documented-and-hoped-for: it is a contract on the sender, enforced before anything enters the path, the same class as `Hello.pane`. The why is the reason the verb exists as much as the command is — the log of *when and why* the fleet decided to clear or compact is the reasoning chain a later self-improvement pass reads. An optional one would be skipped.
- **The allowlist is `["/clear", "/compact"]`, matched on the command word** (Tier 2, in `command.rs`). Arguments pass, so `/compact keep the parser` is one command and `/compactify` is not one at all. Refusal happens **only at accept time**, against that constant, with a sentence for the sender's stderr — the same refusal class as the self-send guard, which D-034 explicitly keeps. Nothing is written and nothing is logged when a command is refused; after acceptance nothing delays, drops or alters it.
- **Control characters are refused, not stripped** — the one place this diverges from `message::sanitize`, deliberately. A mangled message that lands beats a clean one that doesn't; a mangled *command* is a different command. It also keeps `sanitize` untouched, which the empty-diff criterion required.
- **Self-targeting is allowed for `cmd` and only for `cmd`.** `fleet cmd self "/compact …"` is the ordinary use — a worker pruning its own context between task blocks. The message self-send guard at `hub.rs` and its pinning test are byte-identical, and one test now asserts both facts together so the two can never quietly converge.
- **The spike overruled the plan on the delivery mechanism.** WP-03's doc specified raw unpasted bytes, on the theory that a bracketed paste makes `/` literal. Measured against CC 2.1.223 (`docs/command-channel-notes.md`, six live runs): **typed** commands fire the wrong menu entry; a **bracketed paste** filters and selects correctly. So the command path is a new *caller* of `write_paste` with an unframed body, and the 30 ms `SUBMIT_GAP` needed no change — the plan's "does the menu need a longer gap" question answered itself as no.
- **A command is never joined into a message batch.** The per-pane serial writer drains concurrent messages and joins them with a blank line (D-039); a command inside such a join would not have its `/` in column 0. So `spawn_writer` splits a drained batch into *runs* — consecutive messages join exactly as before, byte for byte, and every command is a write of its own. Same queue, same writer task, so a command still cannot interleave with an in-flight paste.
- **`FleetEvent::Command { from, to, command, why, accepted, detail }`,** rendered as its own card in the Messages record and its own gold line in Activity. Not a `Notice` (which would bury the reasoning chain) and not a marked `Message` (which would put words in a pane's mouth). The UI says `accepted — the bytes reached the terminal` and never that the command ran.
- **Two measured failure modes are accepted rather than engineered around.** A command landing on a non-empty input box is concatenated and submitted as prose; a command landing mid-turn is queued by CC and executes when the turn ends. Both are invisible from this side, which is exactly why `accepted` has never meant "executed" (Tier 1.5). A line-kill prefix would fix the first and was **not** taken: on `orch` it silently destroys what the operator was typing, and that trade is not a builder's to make. Recorded in the notes with its cost attached.
- **No automation, and none is coming from here.** No "compact at 80%" daemon, no system-triggered commands. An agent decides and owns the why; auto-anything here is the deleted supervisor growing back.
- **What would reverse it.** A CC release that changes how a pasted slash command is parsed — the menu-ranking of a bare `/clear`, the concatenation behaviour, or the mid-turn queueing. `docs/command-channel-notes.md` is version-stamped against 2.1.223 and names those three as the claims most likely to move. Also: a live shakedown showing the concatenation happening often enough to be worth the line-kill trade.
- **Cost, measured — over budget, and said out loud.** The rendered orch brief goes 1,637 → **1,885** tokens and the worker 1,115 → **1,343** (DeepSeek Flash tokenizer, `examples/system-prompt-spike/count.py`): **+248 and +228**, against WP-03's budgeted ~120 *across both*. Roughly four times the estimate. Where it went: each brief needs the verb line, what the two commands do, the allowlist boundary, and the rule that makes the verb worth having — the worker's "between tasks, never mid-task" timing bound, the orchestrator's "re-brief a worker you cleared" with its consequence. Every one of those is pinned by a test because shortening it turns it into advice. The honest options were "spend it" or "ship a verb nobody uses correctly"; this took the first. WP-09 audits the sum and is now carrying a visible overrun rather than a hidden one.
- **Verified:** 93 workspace tests and 59 shell tests green, `tsc --noEmit` and `vite build` clean. New pins: the unframed keystrokes against a real fake-pane pty in a burst with two messages (the command alone, in arrival order); the allowlist refusal reaching no pty and writing no event; self-command accepted while the message self-send is still refused in the same test; a command never becoming a reply target; and the run split asserting that a messages-only batch still produces `join`'s exact bytes.
