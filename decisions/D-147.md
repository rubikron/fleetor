id: D-147
title: "`Harness::pane_env` carries per-pane environment; opencode's is `OPENCODE_CONFIG_CONTENT` with model, agent and deny rule"
phase: "WP-32"
status: alive
---

- **What.** A new required trait method, `pane_env(&Seat) -> Vec<(String, String)>`, applied last by the orch and worker builders in `spawn.rs`. Claude Code and codex return nothing. opencode returns `OPENCODE_CONFIG_CONTENT` = `{model?, default_agent: "fleetor", agent.fleetor, permission.external_directory: "deny"}`.
- **Why.** The operator's call, 2026-11-02. opencode takes its model only from config, and the seam had two model channels (env name, argv flag), neither of which fits. Measured: `OPENCODE_CONFIG_CONTENT` beats a target repo's `opencode.json` (model, `default_agent`, `external_directory: allow` all lost to it), while a config-dir file loses to it — so a repo could otherwise swap out the brief's agent or widen the deny rule. Rejected: `Posture::model_config_key` + `Seed::model` (smaller, but the repo wins).
- **Reverses if.** opencode's default command takes `--model` and `--agent`, and project config stops outranking the config dir.
