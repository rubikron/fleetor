id: D-025
title: "Phase 4f: the lead can interrupt / restart a worker; the async→sync yank is a kill-by-pid over one `RunnerCommand` channel; a deliberate kill is `Interrupted`, not `Crashed`"
phase: "4f"
status: alive
---

- **What:** Two new lead ops, `Op::Interrupt { slot }` and `Op::WorkerRestart { slot }` (with matching shim lead tools `interrupt` / `worker_restart`), let the orchestrator yank a busy worker. The hub's single dispatcher channel is generalized from `AssignCommand` to a `RunnerCommand` enum (`Assign(AssignCommand)` / `Interrupt { slot }` / `Restart { slot }`); the hub routes control ops through the same slot-validated, dynamic-only path as `assign` (a static fleet answers a clean error). In the dynamic runner, each spawned worker now carries an `Arc<WorkerControl>` — a shared handle holding the worker's **pid** (published by `run_ticket` the instant `Session::spawn` returns) and an `interrupted` flag. `WorkerControl::kill()` sends `SIGKILL` to that pid (via `libc`, already in-tree); the worker's stdout stream then closes, the *sync* supervisor loop sees `Recv::Closed` and unwinds normally, and the runner **relabels** that worker's `Crashed` outcome to the new `Outcome::Interrupted` (only when it initiated the kill). `Restart` kills the live worker and re-dispatches its ticket through the same factory, producing a fresh worker in the slot. The command loop keeps a per-slot `HashMap<u8, (Arc<WorkerControl>, Ticket)>` (touched only by the one loop, so no lock).
- **Why:** This is the async↔sync interrupt D-021 explicitly deferred as "a real feature, not a stub" — the hard part is signalling a worker whose supervisor runs on a `spawn_blocking` thread with no async cancellation point. Killing by pid is the clean, reversible seam: it reuses the stream-close the supervisor *already* handles (no new state machine, no restructuring of `Session` ownership), and `libc::kill` needs no cross-runtime channel. Generalizing the existing dispatcher channel (rather than adding a second) keeps one ordered command stream lead→runner, so an `interrupt` can't overtake an in-flight `assign` for the same slot. Relabelling `Crashed`→`Interrupted` at the runner (not in the supervisor) keeps the sync loop untouched and honest: a stream-close the operator *caused* is not a crash, and the flag lives on each worker's own control so a later real crash on a reused slot is never mislabelled.
- **Deferred / not silent (BUILDING §9):** `worker_restart` is proven at the mapping + routing level (shim tool → `Op` → `RunnerCommand`, shared with the interrupt seam) but its full kill-then-respawn is not yet an end-to-end integration test (the two-worker timing is fiddly against fake-claude; the kill mechanism it depends on *is* proven end-to-end by the interrupt test). SIGKILL is a hard kill (no graceful drain / SIGTERM-then-wait); a worker mid-write leaves a partial worktree, which the git-branch isolation already contains. Windows is unaddressed (unix `kill(2)`), consistent with the rest of the unix-socket stack. `interrupt` cannot yet target the lead's own turn (it is the operator's TTY).
- **Verified:** `orchestrator::lead_interrupt_yanks_a_busy_worker` — a `hang` worker (consumes its assignment, never reports) is assigned, driven to in-progress, then `interrupt`ed; the run ends `Outcome::Interrupted` (not `TimedOut`/`Crashed`), proving the pid-kill reached the sync supervisor before the idle watchdog and that the deliberate close is relabelled. The shim lead-tool mapping tests gain `interrupt`/`worker_restart` (drift guard + "every listed lead tool is translatable"), and the cross-process bridge test is updated for the `RunnerCommand` channel. Full workspace suite green; `cargo check` on the shell (separate workspace, path dep on the changed server) passes. No live-CC spend — deterministic against fake-claude.
- **Reverses if:** a graceful interrupt is wanted (SIGTERM + grace window before SIGKILL, or a cooperative cancel token the supervisor polls) — `WorkerControl::kill` is the one place to change; or if the fleet ever needs Windows workers (swap `libc::kill` for a portable process-kill handle); or if per-slot ordering guarantees are relaxed and control commands want their own priority channel.
