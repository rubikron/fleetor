- **What:** The shell stops simulating and starts orchestrating. `src-tauri/src/fleet.rs` replaces the idle static hub (`bind_hub_idle`, `Hub::new`) with **`run_dynamic_fleet`** on the app runtime: the hub is bound `with_dispatcher`, so an `assign` from the lead spawns one supervised worker per ticket. The runner's `driver` is a pure **lifetime gate** (`tokio::sync::Notify`, fired on window close) — this backend never occupies the lead seat; it only keeps the hub up and drains workers cleanly at shutdown. The lead seat is the operator's real `claude` TUI in the pty (`pty.rs`): it spawns in the **scratch git repo** (`~/.fleetor/_shell/repo`, `git init` on first run) with a generated `fleet` MCP config (the shim, `FLEETOR_ROLE=lead`, `FLEET_SOCKET`), `--mcp-config`, `--add-dir <shell_dir>`, and `mcp__fleet` on the allow-list, inheriting the operator's own environment (their Opus) — **not** the isolated DeepSeek config the workers get. A new, testable **worker factory** (`build_factory`) turns each assigned ticket into a `WorkerSpec`: **fake-claude by default** (a `FakeWithEnv` that carries `FLEET_SOCKET`/`FLEETOR_SLOT` and dials the hub — the free proof path), or a real Flash `WorkerConfig::probe(...).with_wiring(FleetWiring{...})` when `FLEETOR_WORKER_BACKEND=real` (+ `DEEPSEEK_API_KEY`). The choice (and any real→fake fallback when the key is missing) is announced on the feed as a `Notice`, never silent. `fleet_demo` and the `demo` module are deleted; a new `fleet_config` command feeds the top bar the **real** target/branch/worker-backend/gate. The UI drops the dev toolbar (demo + manual assign — the latter only seeded the board, never dispatched, so it would mislead), fetches config in `useFleet`, and gates the lead spawn behind an explicit **start-session** affordance in the terminal pane (the xterm view mounts immediately; `pty_spawn` fires only on the operator's click).
- **Why:** All the machinery existed after 4d — a dynamic hub, a `WorkerFactory`, a `driver` seam, and the shim's lead role — so 4e-2 is *wiring*, not new architecture (KISS): the closure D-021 said "already models" the real orchestrator process is realized as the shutdown gate, with the external pty `claude` filling the lead seat over the socket exactly as the 4d test's fake lead did, only now it is a real model. The `fleet://event` → follower → webview contract (D-022) is untouched; the real fleet already emits the full event set the UI renders (supervisor: `WorkerState`/`ToolActivity`/`TicketState`/`ReportFiled`; hub: `WorkerState` on ask/reply, `Mail`, `ReportFiled`; quality: `GateResult`/`ReviewResult`), so the band, board, and Fleet graph animate on a live run with no UI change. The token line is where 4e was split (operator's call): this phase is **wired but zero live spend** — fake workers keep the first proof near-free, the start gate keeps the operator's Opus from spawning by accident, and the scratch repo holds the whole run inside a `rm -rf`-able dir (Tier-1). Deleting `demo` (rather than keeping a hidden replay) honors the operator's instruction; the fake-worker backend is the new cheap animation path.
- **Deferred (stated, not silent — BUILDING §9):** the **first live run itself** (operator-triggered — start the session, dispatch a scratch ticket, then flip to real Flash); **top-bar cost/token metering** (no cost `FleetEvent` exists; the supervisor parses `Usage` but nothing aggregates it — a real sub-phase, shown honestly as absent rather than faked); re-spawning the lead after it exits (the pty session is sticky — `pty_spawn` no-ops once a session exists, the retained 0.5 limitation); and clean worker drain on hard window close (the shutdown gate is best-effort — the OS reaps children, worker idle-timeouts backstop orphans).
- **Verified:** two new `fleet::tests` — `real_factory_wires_the_worker_to_the_hub` (a real spec carries a `WorkerConfig` with `FleetWiring` at the ticket's slot + socket for the runner to materialize) and `fake_factory_carries_socket_identity_without_a_config` (a fake spec has no config but its command env carries `FLEET_SOCKET`/`FLEETOR_SLOT` so it dials the hub) — plus `cargo check` (backend compiles against the crates), `tsc --noEmit && vite build` (clean, 45 modules), and the **55 crate tests untouched** (no `crates/` changes). No live-CC spend: the factory is proven deterministically; the live Opus+Flash run is the operator gate, like the 0.5 pty visual gate before it.
- **Reverses if:** dynamic assign subsumes the static path entirely (collapse `run_fleet` into `run_dynamic_fleet` with an empty driver, as D-021 foresaw); or the shell should talk to a *daemon* fleet server over IPC instead of hosting the runtime in-process (then `fleet.rs` connects a follower + a lead/dispatch client over the socket rather than owning them) — the `fleet://event` and lead-MCP contracts are unchanged either way; or the fake-worker backend proves unnecessary once real Flash runs are cheap/trusted enough to be the default.
