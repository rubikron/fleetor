- **What changed.** `WORKER_WINDOW_TOKENS` (D-046's 128,000 — its own text called it a guess pending a real number) becomes **500,000**, operator-set. `spawn::worker_command` now exports `CLAUDE_CODE_MAX_CONTEXT_TOKENS` from that same constant, so CC's auto-compact bookkeeping and the context gauge's denominator are one spelling that cannot diverge. Orch is untouched — its model is recognized and its window is not ours to state. The 80%-notice test now derives its fixture from the constant instead of hardcoding 80% of the old one. Pinned by `a_worker_is_told_the_window_the_gauge_divides_by`.
- **Why the default lost.** The WP-02 finding surfaced live: CC 2.1.223 does not recognize `deepseek-v4-flash`, warned it would hold sessions to an assumed 200k, and named this exact env var as the remedy. The operator stated 500k as the window to operate to (2026-08-06).
- **What would reverse it.** A confirmed published window for the worker model that differs from 500k — change the one constant, everything follows. If a future CC recognizes the model name natively, drop the env export only after verifying CC's native number matches the constant; until then the export is the honest statement.
