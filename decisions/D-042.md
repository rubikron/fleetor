---
id: D-042
title: "the briefs stop being Rust and become `prompts/*.md`"
phase: "meta"
status: alive
---

- **The default that lost was "brief text is a `format!` literal in `fleetor-core`."** It was a fine default while the briefs were two paragraphs nobody was arguing about. It stopped being one the moment the briefs became the thing most likely to need iterating: `decisions.md` D-031 records that they are **unvalidated against a live Flash worker**, and the fix for a misbehaving worker is almost always a sentence, not a function. Putting the one part of this system that most wants a fast loop behind a Rust rebuild was backwards.
- **What changed.** `prompts/` at the repo root now holds the prose — `orch.md`, `worker.md`, and two fragments, `delivery-contract.md` and `broadcast-rule.md` — plus `launch.conf` for the worker's model, endpoint and permission mode. `brief.rs` keeps them with `include_str!` and becomes a renderer (`render_orch` / `render_worker` / `render`) and a validator (`validate_orch` / `validate_worker`). `src-tauri/src/prompts.rs` adds `PaneContext::resolve`, which reads the operator's own copies from `~/.fleetor/prompts/`.
- **Baked in *and* on disk, not one or the other.** `include_str!` means the binary always has a working brief, the tests still pin what ships, and there is no runtime path where a missing file produces an unbriefed pane. The disk copy is an override, never the source of truth.
- **The mechanism moved; not one byte of prose did.** All five rendered briefs are identical to what the `format!` literals emitted, `--append-system-prompt` is unchanged, and `launch.conf` carries the old `DEEPSEEK_BASE_URL` / `MODEL_FLASH` / `auto` constants verbatim. That was the point: a change of substrate and a change of content are two arguments, and reviewing them together means reviewing neither. What a pane is *told* is the next argument.
- **Two clauses are composed in, not written out — and a template that dropped one is refused.** `{delivery_contract}` is the only reason a model can tell a failed send from a good one (L3: `accepted` is not `delivered`, and the model's own exit code is the only correction available). `{broadcast_rule}` is the only mitigation left for broadcast amplification, because D-031 removed the rate limiter and Tier 1.4 forbids putting it back. So the operator may rewrite every word around them and cannot lose them. Validation also refuses a rendered brief that has stopped teaching a `fleet` verb — same failure `VERBS` exists to catch, now reachable by editing a file.
- **Every override outcome is announced.** Loaded → `Info` naming the file. Refused → `Warn` quoting the validator's complaint and saying the built-in is running instead. Absent → silence, the ordinary first run. A prompt change that quietly did nothing is indistinguishable from one that did not work, and the operator would then be reading a live fleet's behaviour against a brief it is not running. Same reason an unrecognised `launch.conf` key is a warning rather than a skip: a typo'd `permission_mode` reads exactly like a working config until a pane wedges on its first tool call.
- **Resolved once at bootstrap, not per spawn.** A fleet whose panes were briefed from two revisions of a file the operator was editing is not a fleet anyone can reason about. Edits take effect next launch — the same rule `fleet_pick_target` already follows, and a system prompt cannot be changed after `exec` anyway.
- **`fleetor-core` still does no I/O.** The app reads files and hands templates in as arguments; core renders and validates. And the briefs still go in as a system prompt, never as a `CLAUDE.md` in a pane's cwd (Tier 1.1) — `src-tauri/tests/panes.rs` still pins that.
- **What would reverse it.** Evidence that the file rung is a hazard rather than a help: an operator override that gets a pane into a state validation cannot describe, or a `~/.fleetor/prompts/` copy silently going stale against a shipped brief that moved on and nobody noticing because the Info notice reads as normal. The cheap partial retreat is keeping `prompts/` as the source of truth and dropping only the `~/.fleetor/` override rung — the split is already exactly there.
- **Verified:** 63 workspace tests and 44 + 9 shell tests green (the 9 are the real-pty pane tests against `fake-pane`), `tsc --noEmit` and `vite build` clean. The five rendered briefs were captured from the pre-change binary and diffed byte-for-byte against the post-change ones. Coverage of the new paths: no override directory is silent, a valid override is used and announced, a broken one falls back and names the placeholder to restore, `launch.conf` overrides only the keys it sets, an unknown key warns without discarding the good lines, comments and blank lines are not complaints, a brace in prose survives rendering, the shipped templates pass their own validator, and the baked `launch.conf` is pinned to the `LaunchConfig` fallback so the two cannot drift.
