---
id: D-035
title: "Phase 2: the headless fleet is unwired from the app, and the socket half of messaging is proven"
phase: "2"
status: alive
---

- **What:** `src-tauri` no longer runs a fleet. `spawn_pool_fleet`, `build_factory`, `WorkerBackend`, `FakeWithEnv`, `resolve_backend`, `fake_script_path` and `shim_path` are gone, along with the four headless standby workers they produced; the `fleetor-cc` dependency goes with them. What replaces all of it is one line of intent — `Hub::with_app(store, HubConfig::default(), app_tx).run(transport)` — plus the pane seam the hub talks to. The store, the live bus and the follower→webview pump are untouched, which is why the feed still streams. `fleet.rs` went 689 → ~430 lines.
- **The target replaces the scratch repo.** `~/.fleetor/config.json`'s `target` names the repo the fleet works on; absent or unusable, it falls back to a seeded testbed at `~/.fleetor/testbed/` with a `Notice` on the feed. A config that names *nothing* is the ordinary first-run case (Info); a config that names something broken is a Warn that quotes the problem, because reading a typo'd path as "no target configured" would put the fleet in the testbed while the operator believes it is in their own repo.
- **The seed is embedded, not copied.** `include_str!` over `testbed-seed/`, ~9KB in the binary. A path ladder — repo-relative under `tauri dev`, a resource in a bundle — is L4's exact shape: it works in dev and silently resolves to nothing in a bundle, leaving the fleet an empty directory to "work on". Seeding never overwrites an existing file (after the first run this directory holds the fleet's real work) and makes an initial commit, because `git worktree add` needs one and Phase 3 gives every worker pane a worktree.
- **The MCP wiring left `pty.rs` here rather than in Phase 3.** `shim_path()` dies in this phase and `pty.rs` called it, but the deeper reason is that `mcp__fleet__assign / await_events / reply` now point at a hub that spawns nothing. A tool surface that silently cannot work is worse than no tool surface — the orchestrator would call `assign`, receive an `Ack`, and wait. `FLEET_SOCKET` stays: Phase 3's `fleet` CLI reads it.
- **The lead inbox pump and its consumer are deleted together.** `spawn_lead_inbox_pump` long-polled a queue only headless workers ever wrote to. Its consumer — the `lead://inject` queue in `TerminalPane.tsx`, with the 1500ms operator-idle guard and the 400ms one-message-per-tick flusher the D-034 sweep found — went with it. Leaving dead code that implements precisely the pattern this pivot bans is a trap, not a harmless leftover: the obvious next move is to re-point it at message events, and both delays come back with it.
- **The pane seam answers, it does not park.** Until Phase 3's `deliver.rs` exists, `spawn_pane_seam` refuses every `Deliver` with "no panes are running yet" and answers `Roster` with an empty list. It must answer *something* for every command: the hub awaits the ack with no deadline (D-034), so a command received and left unanswered parks the caller's `fleet send` forever. That is the failure mode the unbounded design accepts in exchange for never lying about a delivery, and it is not one to hand out for free.
- **The socket half is now proven.** `a_pane_op_crosses_the_real_socket_and_is_answered` binds the hub on a temp socket, dials it with a real `Client` the way the `fleet` CLI will, sends `Op::PaneSend`, and asserts both the refusal it gets back and the event on the feed carrying the body. Everything before this was in-process against a fake app. `spawn_hub` takes the socket path as a parameter rather than reading `socket_path()` precisely so this is reachable without a window.
- **Deviation, stated:** `tauri-plugin-dialog` was not added. An unregistered plugin dependency does nothing but slow builds and read as wired to anyone reviewing; it lands with the picker that uses it.
- **One user-facing lie fixed on the way past:** the spend gate read `worker_backend` and rendered anything that was not `"flash"` as "fake (free proof path)". With the backends gone the field is `"none"`, so the gate would have promised a free worker path that no longer exists — on the one screen whose entire job is telling the operator what a click will cost.
- **Verified:** `cargo check` clean in both workspaces, no warnings; 9 shell tests + 104 workspace tests, 0 failures; `tsc --noEmit` clean. Not verified: the app launching as a window, which needs a GUI session.
