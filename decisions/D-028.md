id: D-028
title: "Phase 4i: worker transcripts in the shell; worker stderr finally captured (was dropped), surfacing the reason a headless worker dies"
phase: "4i"
status: reversed
---

- **What:** A per-worker **transcript view** in the shell (a new "Workers" sidebar tab / `WorkerTranscripts.tsx`), fed by the same event bus as everything else. The supervisor emits two new `FleetEvent`s — `WorkerSaid { slot, ticket, text }` (the worker's assistant text, previously parsed only for the report-scrape and never surfaced) and `WorkerExited { slot, ticket, ok, detail }` — which flow through `BroadcastStore` → follower → `fleet://event` → a per-slot `reduceTranscript` fold in `useFleet`. The view also folds in `Mail` addressed to a worker (a "◀ mail from lead" marker), so orch→worker steering shows in the worker's transcript. Clicking a band worker cell opens it. **Crucially, `Session` now captures the child's stderr** (a second reader thread → bounded `stderr_tail()`); it was piped-and-dropped, so a worker `claude` that crashed on launch died silently. `WorkerExited.detail` carries that stderr tail on every failure path — including the `assign()` broken-pipe path a die-on-startup worker hits (which previously left the ticket stuck at `Assigned` with no visible reason).
- **Why:** The orchestrator is a real TUI we mirror byte-for-byte, but workers are **headless** stream-json processes — their "chat" is structured JSON we already capture to disk; rendering it gives full visibility with **zero change to the supervision model**. Emitting through the store (not a new Tauri channel) keeps `fleetor-server` Tauri-agnostic and makes transcripts replayable (the follower replays from seq 0, so a freshly-opened tab is populated). The stderr capture closes a real observability hole that was actively hiding the current live-worker crash. **tmux-TUI workers were considered and rejected** (operator asked): a full interactive TUI per worker would force the supervisor to screen-scrape and inject keystrokes, throwing away turn detection, report ingestion, pid-interrupt, the D-015 mail-delivery paths, and the fake-claude deterministic tests — a large rewrite of Phases 1–4 for visual parity we get free from the transcript. Headless is kept.
- **Verified:** `cargo build`/`cargo test` green across the crates workspace (22 test binaries, 0 warnings), `cargo check` clean on `src-tauri`, and `tsc --noEmit && vite build` clean — the `type`-discriminated `FleetEvent` union makes the two new variants a compile-time obligation in both the reducer and `EventFeed` (contract-drift-as-type-error). Free live check: fake-backend workers run and populate the Workers view with zero spend; the real-backend worker that currently dies will now emit `worker-exited { ok:false, detail:<stderr> }` — the crash reason, shown in the panel.
- **Deferred (stated):** the worker-spawn crash **fix** (this makes the reason *visible*; the fix follows once we read it); full delivered-mail **body** in the transcript (the event log carries mail metadata, not the body — the marker has no text yet); tool-call **inputs/results** (v1 shows tool names via the existing `tool-activity`); tmux-TUI workers (rejected).
