- **What.** Operator's call, 2026-09-11, choosing option 1 of two: `teardown_fleet` (window close and `RunEvent::Exit`) now kills the panes, drops the live fleet — which closes its store, since every task holding it runs on the fleet's runtime — and then runs `runs::rotate`. D-085's launch-time rotation stays, and normally finds an empty slot; after a crash, Force Quit or `kill -9`, where no quit hook runs, it is what archives the session. Bootstrap's rotation stays for the reopen switch. Three call sites of one function, not three mechanisms. Built as WP-28 (`docs/roadmap/28-archive-on-quit.md`).
- **Why close, when D-085 already made the row appear on launch.** Seen from inside the app the two are identical; seen from outside they are not. D-059 makes `runs/` a directory agents read *without* the app running, and under D-085 alone the last session is missing from it for as long as the app is closed.
- **Why not close alone.** D-058's reason for rotating at start — a crash never loses a run — would be given up: the close hooks are best-effort and do not run on a crash.
- **The store must close before the archive, and that order is the load-bearing part.** `archive::freeze` cannot leave WAL mode while another connection holds the database ("something else holds it open"), and rotation then falls back to moving three files. `fleet::shutdown` only notified the hub before this; it now also takes the fleet out of state, exactly as `run_reopen`'s teardown already does.
- **Accepted:** the "previous run archived — see History" notice written at quit is lost with the process; the row itself is the evidence. Rejected: option 2, keeping launch and Start only.
