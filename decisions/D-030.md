---
id: D-030
title: "The 5-TUI messaging pivot: MCP and the headless supervision model are deleted; all five agents become live `claude` TUIs"
phase: "meta"
status: superseded
---

- **What:** A ground-up narrowing of the product to *messaging + visibility*. The MCP shim (`fleetor-shim`), the headless stream-json supervision model (`supervisor`/`quality`/`gate`/`runner`, `fleetor-cc`), and the whole ticket/board/report/review apparatus are deleted. In their place: **1 orchestrator + 4 worker `claude` TUIs**, each in its own pty owned by the Tauri app, each viewable in the shell (orch fixed left, workers tabbed right). Agents address each other through a small **`fleet` CLI invoked via Claude Code's built-in Bash tool** (`fleet send 2 "…"`), a plain socket client — no MCP, no JSON-RPC. The hub survives as a pure router; `fleetor-ipc` and the `BroadcastStore` event bus survive untouched. Plan: `docs/tui-pivot-plan.md`. Phase 0 findings: `docs/tui-spawn-notes.md`. Branch `feat/tui-fleet`.
- **Why:** Mapping the as-built system (`docs/fleet-comms-map.md`) showed two things. First, **messaging is the only part that works** — the shipped app runs `run_pool_fleet`, where `RunnerCommand::Assign(_) => {}`, so a lead's `assign` returns `Ack`, lands the ticket on the board as `Backlog`, and nothing ever runs or moves it; gate/review/report are unreachable from the app entirely. Second, and decisively, **the headless model is what forces the complexity**: mail has to be queued and drained at turn boundaries (three delivery paths, a Stop hook, an atomic `take_mail`) *only* because a `-p` process has no writable stdin between turns. Turn detection, report ingestion, transcript reconstruction and pid-interrupt all exist to compensate for not having a terminal. A live TUI has an always-writable stdin, so all of it becomes **unnecessary rather than merely unused** — delivery is just "write bytes to the target pty." Net ~3,500 lines out. This also reverses D-028's "tmux-TUI workers rejected" and D-029's deferred "Claude-TUI-per-worker" — that pivot is now the product, because the operator wants to *watch and steer* four agents, not run a one-shot ticket pipeline.
- **Consequences accepted:** No queue — a send to a dead pane fails loudly (nonzero exit + stderr) rather than buffering; the model self-corrects from its own Bash result. No blocking — `ask_lead`, the waiters, the ask timeout and `WorkerState::Blocked` all die. Message **bodies** move into the event log (`FleetEvent::Mail` carried metadata only, which is useless for a product about watching messages). `session = worker` (D-029) becomes permanent. Delivery is honest best-effort: the event field is `accepted`, never `delivered` — we queued bytes to a live pty and cannot know the model read them. Worker transcript reconstruction is abandoned outright (the TUI *is* the view); parsing redrawn ANSI to rebuild it is explicitly rejected.
- **Verified (Phase 0, real CC 2.1.220, no app code changed):** The onboarding wedge is **absolute, not intermittent** — a virgin `CLAUDE_CONFIG_DIR` never reaches a prompt, and the four worker config dirs on disk are in exactly that state. Bisected to a **two-key** minimum seed (`hasCompletedOnboarding` + `projects[cwd].hasTrustDialogAccepted`; `theme` unnecessary), with the sharp edge that **`hasTrustDialogAccepted` is keyed by absolute path**, so the target picker must re-seed every pane cwd. `ANTHROPIC_API_KEY` blocks the interactive TUI on api-key approval — only `ANTHROPIC_AUTH_TOKEN` may be set, though `apply_env` currently sets both. Bracketed paste + `\r` submits at 0/10/30 ms, multi-line included. `--permission-mode auto` is prompt-free for Bash/Read (ran the testbed suite, returned the right count) where the default `manual` would wedge. `tauri::ipc::Channel` was **rejected** for now: under its 1 KB threshold raw payloads serialize to a JSON integer array (~4× base64), so Phase 3 ships per-pane event names + base64 + 16 ms/64 KB coalescing instead. New finding: `CLAUDE_CODE_CHILD_SESSION` leaks through env inherit and silently disables transcript saving — add to `env_remove`.
- **Deferred (stated):** Phases 1–6 unstarted. `tauri::ipc::Channel` revisited in Phase 6 behind a measurement. Broadcast amplification is the highest-consequence *new* failure mode (five peers that can all broadcast and are all instructed to be helpful — the old system was immune only because headless workers had no volition between turns); three mitigations are required together, none yet built: a hub-side per-pane token bucket, an explicit "never reply to a broadcast unless it names you" brief clause, and a visible per-pane messages/min rate. An instant write into the orch pane can land mid-line if the operator is typing; accepted, with a "hold" toggle as the fix if it bites.
