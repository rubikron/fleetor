id: D-140
title: "an opencode seat runs on whatever the operator's opencode already has; FLEETOR enforces no login"
phase: "WP-32"
status: alive
---

- **What.** An opencode seat, orch or worker, uses the operator's existing opencode providers and login — today the OpenCode Go plan. FLEETOR stores no key, never asks for a login, and the gate does not refuse an opencode seat for want of one. The operator changes provider or model inside the pane's own terminal.
- **Why.** The operator's call, 2026-11-02: assume the operator is already logged in on their regular CLI tool, and use what is there. This clarifies D-118 rather than reversing it: FLEETOR still knows no credential; opencode's own store stands where a vendor login does.
- **Scope.** opencode seats only, on this branch. Whether Claude Code and codex stop refusing an unreadable login too is a separate decision, after WP-24 and WP-32 merge.
- **Reverses if.** An opencode seat needs a credential the operator's opencode does not hold.
