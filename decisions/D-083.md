id: D-083
title: "the light/dark switch morphs every colour together, the way Mintaka's page turns dark, instead of snapping"
phase: "meta"
status: alive
---

- **What changed.** The fourteen colour tokens light mode redeclares are registered with `@property` as `<color>` and transition on `:root` for 600ms, `cubic-bezier(0.65, 0, 0.35, 1)`, so background, text, borders and `color-mix()` move in lockstep with no per-component rule. xterm's canvas is outside CSS, so `TerminalPane` steps the terminal theme over the same duration and curve (`mixTheme`, `easeThemeMorph`, `THEME_MORPH_MS` in `theme.ts`). Source read, not guessed: Mintaka's `WorkPreview` script tweens `.home-dark-section` to `backgroundColor: #18181b, color: #fff` together, scrubbed by scroll; here the switch drives it.
- **The default that lost was an opacity cross-fade**, which dims the content out and back rather than moving colours in place. **Scoped to `[data-theme-morph]`**, set by `useTheme` only for an operator's switch, because the stored theme applied at launch would otherwise morph in from dark on every start. Reduced motion skips it and the switch snaps as before.
- **What would reverse it.** Visible jank from re-theming five WebGL terminals per frame (unmeasured), or a WebKit build where registered custom properties do not transition — then the fallback is the same token change without `@property`, which snaps.
