- **What.** A cursor worker's `cli-config.json` sets `approvalMode: allowlist` and `permissions.allow: ["Shell(*)"]`, so no tool call waits on an approval prompt. The unmodified `write_guardrail.py` is its containment, installed as Claude Code's own entry — `hooks.PreToolUse[{matcher, hooks:[{type: command, command}]}]`, event `PreToolUse` — in `<worktree>/.claude/settings.local.json`, matched on `Shell|Write|Delete`. Supersedes M11, M12, M14 and M28: cursor's sandbox is not used.
- **Why.** Measured on `2026.10.22-27dcf5f` (`cursor-spike-notes.md`): the sandbox never wrapped a command on this account; `unrestricted` writes anywhere; the default prompts and parks the pane. Through the Claude-format hook every outside write — shell, file create, file edit, delete — was refused with no prompt, and inside writes worked. The operator's call, 2026-11-02: contain cursor workers the way Claude Code and codex workers are contained.
- **Cost.** The same deterrence-not-enforcement limit the guardrail has everywhere: a shell command whose write target is built at runtime is not seen (`write_guardrail.py`). The settings file lives in the worktree, so it needs a `.git/info/exclude` line, as the brief's `.mdc` does (M5).
- **Reverses if.** Cursor's sandbox is shown to confine commands on the operator's account without prompting, or cursor stops honouring `hookSpecificOutput` under `PreToolUse`.
