---
id: D-142
title: "an opencode pane is contained by a guardrail plugin calling `write_guardrail.py`, plus `external_directory: deny`"
phase: "WP-32"
status: alive
---

- **What.** `install_guardrail` writes a plugin into `$OPENCODE_CONFIG_DIR/plugins/` whose `execute.before` tool hook runs the fleet's `write_guardrail.py` and refuses the call when the script does. The seat's config also sets `permission.external_directory: deny`, which `--auto` still enforces.
- **Why.** The operator's call, 2026-11-02. opencode has no OS sandbox and an unattended pane needs `--auto`, which approves everything not denied; Tier 1.7 says auto-approve is narrowed, never widened. The plugin gives opencode the same decision Claude Code and codex run. Rejected: the permission rule alone (a shell command still writes anywhere); no `--auto` (an unattended pane parks on every call).
- **Measured.** A v2 plugin is a default export `{ id, setup(ctx) }`, loads from the relocated config dir, and gets `ctx.tool.hook(name, callback)` (`opencode-spike-notes.md` §8). **Not measured:** that a throw from the hook refuses the call — the paid spike's first arm.
- **Reverses if.** A hook cannot refuse a call, or opencode ships a sandbox that refuses a superset of what the guardrail does.
