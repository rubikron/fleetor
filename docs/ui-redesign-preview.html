Design notes

  • No side-tab accent bars. The single most recognizable AI-UI tell (a thick colored border-left on cards) is gone. Board cards now cue state with a full 1px border tint plus the foot dot and chip; the orchestrator anchors on a lifted surface, larger size and the gold "lead" tag, not a rail.
  • Blocked is one colour, coral, everywhere. The band cell (full coral outline, tint, gentle border pulse), board dot and chip, feed rail and the fleet edge all agree. Gold now means only review / pending / unread / cost, so the one "come here" signal never competes with itself.
  • Motion is reserved for that one signal. The "alive" dots are steady; only the blocked worker pulses, and the fleet view moves a single message dot along each active edge in its real direction. Nothing animates for decoration.
  • Fleet view rebuilt as directional flow, not a recolored service map: asymmetric, signal-driven layout (the blocked worker sits closest and largest; the idle one is pushed out and dimmed), arrowheads, and edge labels naming the actual traffic (assign, ask_lead, ticket ids).
  • Accessibility floor raised. Secondary metadata clears WCAG AA (muted grey lightened, 9px steps removed); every interactive element has a keyboard :focus-visible ring; the view tabs carry real tab/tabpanel roles.
  • Orchestrator is the visual anchor and carries real data (model · context · unread · elapsed); the band is no longer six equal cells, so the eye has a first place to land.
  • Dev controls demoted to a quiet top-bar dev toolbar. Open question: should they ship in the product at all, or live behind a dev menu?
  • Open question: the queue cell restates the board's column counts on the Tickets view. It earns its space on the Event log and Fleet views (where the band persists but the board is hidden); worth deciding whether it stays on Tickets or shows something the board can't (oldest backlog age, time-in-review).
