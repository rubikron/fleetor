---
id: D-081
title: "the vendor-binary tier is wired into the conformance suite, runs by default, and shouts when it skips"
phase: "meta"
status: alive
---

- **What changed.** `src-tauri/tests/vendor_binary_tier.rs` — a new, separate test binary that runs `examples/codex-spike/probe.py` and gates on its exit code (the count of failed arms), plus two tripwires: the probe's vendor build id must match `docs/notes/codex-spike-notes.md`, and every URL in the probe must be loopback. The probe was **not** rewritten and no production code was touched. It is a third tier between the two issue #12 named, exactly as C13 specifies.
- **It runs by default rather than behind an opt-in env var, and that is the default that moved.** The obvious alternative — `FLEETOR_VENDOR_TIER=1 cargo test` — costs a machine with the vendor binary nothing, which is precisely what is wrong with it: an opt-in flag is a quiet skip with extra steps, and C13's whole argument is that this tier rots into decoration the moment its absence stops being visible. Cost, stated: **~47 s** added to `cargo test` wherever `codex` is on `PATH` (two non-interactive turns, three sandboxed commands, two real pty sessions), all bounded by the probe's own per-subprocess timeouts.
- **Loud is harder than it sounds, and the mechanism was verified rather than assumed.** `libtest` captures `println!` *and* `eprintln!` on a **passing** test, which is the state every skip is in — so the obvious announcement is invisible in a plain `cargo test`. The skip banner is written to file descriptor 2 directly, which the capture does not intercept; measured on a scratch test binary before the file was written, and then demonstrated end to end with `codex` off `PATH`.
- **Three things are deliberately not skips.** A missing probe (a *deleted tier*, not an absent vendor), a probe that ran and reported no arms (exit 0 with nothing measured — the silent pass this tier exists to make impossible), and a probe that printed its own `SKIP:` while the test resolved the binary (the two disagree about the machine). All three fail.
- **No harness was registered and nothing in `src/` learned the vendor's name.** Phase 1's exit condition is a green suite with exactly one registered harness; the binary is named in `tests/` as the subject of a measurement, the way `tests/write_guardrail.rs` names `sh`. No verb moved; the two existing tiers are byte-unchanged.
- **What would reverse it.** A CI machine where the ~47 s or the vendor binary's own side effects (it writes `/tmp/codex-spike` and briefly binds `127.0.0.1:8731`) make a default-on tier untenable — in which case the answer is a *default-on-with-a-documented-off-switch*, not a default-off flag, because the announcement is the load-bearing part.
- **Verified.** Both paths, on this machine. Running path: `codex-cli 0.153.4` on `PATH`, 8/8 arms PASS in 45 s, zero tokens (the model provider is the probe's own loopback capture server). Skip path: `PATH=~/.cargo/bin:/usr/bin:/bin cargo test --test vendor_binary_tier` — banner printed with no `--nocapture`, no failure, no silent pass. `src-tauri`: 166 lib + 75 integration across 10 binaries, up from 72 across 9. Root workspace: **226**, unchanged — the Tier 1.4 evidence. `cargo clippy --all-targets` adds no warning to the two pre-existing ones.
- **Not verified.** No machine *without* the vendor binary has run the suite for real — the skip path was demonstrated by removing `codex` from `PATH`, not by a machine that never had it. And nothing here measures whether an operator who sees the banner acts on it, which is the assumption C13's "or it rots into decoration" actually rests on.
