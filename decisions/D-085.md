id: D-085
title: "the last session is archived when the app opens, not only when the next fleet starts"
phase: "meta"
status: alive
---

- **What.** Operator's call, 2026-09-11: reopening the app should show the most recent session in History. It did not, twice over. Rotation ran only inside `fleet_bootstrap`, so at the start gate the session just closed was still the live slot (`_shell/state.db`) and not a row; and `useRuns` read the list once when `App` mounted, so even a run archived by that start stayed invisible until a rename, delete, reopen or relaunch. Now `runs::rotate` also runs in the app's `setup`, right after `orphans::sweep` has reaped the last session's panes, and its notices are held on `GateHold` for the feed the way the gate's probe notices already are. The frontend re-reads the list whenever History is shown and after a fleet starts.
- **This amends D-058's "rotated at start", not its reason.** The property D-058 rests on — the previous run is frozen before anything opens a new log, so a crash never loses one — holds, because nothing reads or opens the live slot between launch and bootstrap (checked: `fleet_bootstrap` is the only opener in `src/`). Bootstrap still rotates too, which is what archives the fleet being left on a reopen; at launch-then-start it finds an empty slot and does nothing.
- **Accepted:** the app assumes one instance per machine, as `orphans::sweep` already does — a second window would archive the first's live log out from under it, exactly as starting a fleet in it always could.
