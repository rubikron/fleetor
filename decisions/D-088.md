---
id: D-088
title: "pane terminals run at line-height 1.0, because a pane holds a TUI and a TUI draws boxes"
phase: "meta"
status: alive
---

- **What.** `TerminalPane`'s xterm is constructed with `lineHeight: 1.0` (was 1.2) and `rescaleOverlappingGlyphs: true`. Found from an operator screenshot of a codex pane beside the same codex in a plain terminal, 2026-09-11.
- **Why the old default lost.** 1.2 is a prose virtue and these panes are not prose: xterm draws `│`, `╭` and `─` inside the cell, so any leading above 1 leaves a gap between one row's vertical border and the next, and codex's header panels and composer frame render as dashed columns instead of boxes. Real terminals ship 1.0, and so does xterm's own default; the fix is not a font choice.
- **Also observed and *not* changed (D-088):** codex's boxed header scrolls out of view as a session grows — it does the same in a plain terminal; the `--dangerously-bypass-hook-trust` line in every codex pane is FLEETOR's own flag (C50); and the footer shows an absolute worktree path rather than `~/…` because a fenced worker's `HOME` is not the operator's.
